# 角落绽放 · Corner Bloom

一个面向安卓单手操作的角落应用启动器。右下角上滑，图标旋转散开；手指保持按住，滑到图标后松手打开应用。

当前版本 **0.2.5** · Android 8.0+ · 原生 Java + Canvas。

[下载 0.2.5 APK](downloads/corner-bloom-0.2.5.apk)

## 功能

- 最多 15 个常用应用，支持搜索、选择与排序。
- 上滑确认展开，轻点、停留和小幅抖动不展开。
- 图标不透明，支持旋转回弹动画与边缘柔和的局部雾效。
- 固定的角落入口，不随键盘上移；位置、触发范围、动画和触觉反馈可调整。
- 可选轻点补点：松手后在入口下方同一坐标补一次点击，需要手动开启无障碍服务。
- 可选长按删除辅助：Android 13+，按住已标记的键盘删除键位置连续删字，松手停止继续发送删除。无需 Root 或 Shizuku。
- 可选隐藏最近任务卡片、开机自动启动，常驻通知可停止入口。
- 解锁后复查入口状态，丢失或异常窗口自动有限重试；设置页和常驻通知均可手动恢复入口。
- 可选通过无障碍显示入口，尝试解决系统强制显示的普通悬浮窗提醒，无需 Root。
- 应用内可视化调整位置：拖动亮条移动入口，拖动应用图标交换位置，保存后生效。

## 0.2.5：按 XGesture 的导航方式调整页面切换

- 核对 [XGesture 的 MainNavHost](https://github.com/qpst4/XGesture/blob/d39094b3400ebc8a35a1331ab3f59492e867cf47/app/src/main/java/com/slideindex/app/ui/navigation/MainNavHost.kt) 及其使用的 [Miuix 0.9.4 默认转场](https://github.com/compose-miuix-ui/miuix/blob/v0.9.4/miuix-nav/src/commonMain/kotlin/top/yukonga/miuix/kmp/nav/transition/NavTransitions.kt)，以原生 Java 实现相同的导航思路：新页面保持实色、原尺寸，从右侧整页进入；下层页面移动四分之一宽度，轻微压暗；返回时反向还原。按 Miuix 的 500ms 曲线控制节奏，无过冲、无回弹。未引入 Compose 或 Miuix 依赖，也未复制 XGesture 的应用代码。
- 二级设置和位置编辑改用同一个 Activity 内的保留页面栈，删除全屏对话框转场。首页滚动位置保留；从常用应用进入位置编辑，再返回常用应用时不会闪过首页。
- 移除 0.2.4 自定义的整页透明叠加、弹窗缩放与上下移动。应用选择弹窗回到系统默认效果，保留列表复用与刷新优化。
- 快速重复点击不叠加页面，进入中按返回从当前位置反向退出；关闭动画、切到后台和销毁页面时清理动画与编辑状态。Android 13+ 注册系统返回回调，旧版保留返回键处理。

沿用旧版签名，可覆盖安装并保留设置。主机检查覆盖页面堆栈、进入中返回、嵌套返回和清理；尚未在目标手机验证窗口绘制与实际帧率。

## 0.2.2：可选无障碍入口

如果系统把“正在其他应用的上层显示内容”通知开关锁灰，可尝试此模式：

1. 覆盖安装 0.2.2，打开应用首页的「通过无障碍显示入口」。该选项默认关闭。
2. 保持系统中的「角落绽放 · 点击穿透」无障碍服务开启，返回应用点「恢复入口」。
3. 确认状态显示「无障碍入口已挂载」，再测试上滑、轻点和长按删除。

此模式由已连接的无障碍服务显示手势入口与动画画布，标记删除键时也使用相同方式；无需普通悬浮窗权限。按 AOSP 的通知触发逻辑，无障碍窗口不属于普通警示悬浮窗，通常不会产生截图中的提醒。这是实现依据，**尚未在一加 Ace 5 实测通知是否消失**，也不保证系统没有其他无障碍提示。应用自己的运行通知保留停止和恢复按钮。

无障碍断开时入口暂停，连接恢复后重建窗口；不会自动切回普通悬浮窗。关闭此选项可恢复普通模式，普通模式需要原悬浮窗权限。没有新增读取窗口内容、触摸探索或网络能力。两种模式的键盘层级、动画和系统手势兼容性仍需真机验证。

沿用 0.2.1 签名，可覆盖安装并保留设置。

## 0.2.1：入口消失后的恢复

- 修复锁屏/解锁广播早于系统状态更新时，入口可能一直保持隐藏的问题。亮屏时持续复查；息屏时暂停，不使用唤醒锁。
- 窗口脱离、布局操作失败、入口透明或不可触摸时，空闲后修复。单轮最多尝试三次，避免反复抢占窗口。手势、补点或长按删除期间延后恢复。
- 新增「入口不见了？恢复入口」和通知中的「恢复入口」，主动重新挂载两个窗口。正常检查不会反复把窗口提到其他悬浮窗上面。
- 前台服务请求系统在进程回收后恢复；返回设置页时检查或恢复先前开启的服务。手动关闭后不自动重新开启。厂商强制停止和后台限制仍可能阻止恢复。
- 页面区分服务停止、锁屏隐藏、窗口已挂载、正在重试和恢复失败。**已挂载不等于肉眼可见**：其他悬浮窗可能遮挡入口，安全页面也可能由系统隐藏第三方悬浮窗；离开该页面后再试。

沿用 0.2.0 的签名，可覆盖安装并保留设置。尚未完成一加 Ace 5 真机验证。

## 安装与使用

1. 安装上方 APK，打开「角落绽放」，选择并排序常用应用，建议 9–15 个。
2. 在「位置与排列」预览并拖动调整入口与图标，点击保存。
3. 按应用提示授予悬浮窗权限，点击「开启角落手势」。从右下角亮条上滑，保持按住，滑到图标后松手打开；没有选中图标时松手取消。
4. 如需点击入口下方的键盘按钮，开启「轻点穿透」，并在系统无障碍设置启用「角落绽放 · 点击穿透」。这通过补点实现，存在少量延迟。
5. 如需按住删除，开启「按住删除键连续删（免 Root）」，点击「标记键盘删除键」，在临时标记层点一次键盘删除键中心。换键盘布局、高度、屏幕缩放或方向后重新标记。

长按辅助只针对底部固定文字键盘、同一文字编辑器和已标记的删除位置；不是通用的原始长按触摸转发。数字/电话输入框、悬浮键盘和自定义编辑器可能不支持。输入法候选或组合输入的表现取决于输入法实现。

最近任务隐藏与自启动在「后台与启动」开启。无障碍入口、轻点和长按删除在「显示与穿透」中设置，动画、入口大小和雾效在「外观与手感」中调整。自启动还受系统后台和电池管理限制；应用被强行停止后需手动打开。系统底部手势保留区域可能与入口冲突，可调整入口位置。

## 权限与隐私

应用未声明网络权限。普通模式的悬浮窗权限用于显示入口与启动器；可选无障碍模式使用已连接服务的窗口。前台服务和通知用于持续显示运行状态与停止入口；开机广播仅用于可选自启动。

无障碍功能由用户手动开启，未请求读取窗口内容。可选无障碍入口显示交互窗口；轻点使用手势注入；长按删除通过无障碍输入编辑接口发送成对的删除键事件，不查询或保存输入文本。

## 构建

安装 JDK 17、Android SDK platform 35、build-tools 35.0.0。可用 Android Studio 打开项目，或使用 Gradle 8.9：

```bash
gradle :app:assembleDebug
```

项目未包含 Gradle wrapper。也可使用独立构建脚本：

```bash
export ANDROID_SDK_ROOT=/path/to/android-sdk
bash tools/build.sh
```

独立脚本另需 Python 3，输出为 `app/build/manual/corner-bloom-0.2.5.apk`。只有 JRE 时，可设置 `BLOOM_ECJ_JAR=/path/to/ecj.jar`；也可通过 `BLOOM_ANDROID_JAR` 和 `BLOOM_BUILD_TOOLS` 指定 SDK 文件位置。

**仓库不包含签名私钥。** 独立脚本会在本地生成开发密钥；Gradle 使用本机的调试签名。新生成的密钥与已发布 APK 不同，不能直接覆盖安装已发布版本。请保管自己的签名密钥，不要提交到 Git；卸载会清除应用设置。
