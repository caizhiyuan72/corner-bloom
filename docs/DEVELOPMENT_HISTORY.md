# 角落绽放 · Corner Bloom 0.2.0

给安卓日常单手操作做的角落应用启动器原型。右下角上划展开，保持按住，滑到图标后松手打开。没有长按等待。图标沿不同轨迹散出、旋转、轻微回弹，最终落在固定位置。

## 0.2.0：加回专门的长按删除辅助（免 Root）

本版按用户明确的需求实现：按住入口下方的删除键位置连续删字，松手停止继续发送删除。使用 Android 13/API 33 的无障碍输入编辑接口，不使用触摸探索或真实触摸接管，不将固定时长长按重放到键盘。保留 0.1.9 的轻点补点与快速上滑路径。

### 开启与测试

1. 覆盖安装 0.2.0，无需卸载；原位置、常用应用、动画、雾效、最近任务隐藏和自启动设置保留。
2. 保持「轻点穿透」及对应无障碍服务开启，再开启「按住删除键连续删（免 Root）」。长按辅助默认关闭，需要 Android 13 或更高版本；无需 Root 或 Shizuku。
3. 点击「标记键盘删除键」。应用会在测试输入框调出键盘，并显示临时标记层；点一下键盘删除键的中心。这次点击只记录位置，不删除文字。上方提示区域可以取消；离开设置页也会移除标记层。
4. 开启角落手势后，在测试输入框内先试轻点，再在入口覆盖删除键的位置按住，观察连续删除与松手停止，然后测试快速上滑。若删除键没有被入口覆盖，原键盘会直接处理长按，不需要辅助。
5. 换键盘布局、旋转或改变屏幕缩放/键盘高度后重新标记。此辅助针对底部固定的文字键盘，数字/电话等输入框不启用，悬浮键盘等没有可用 IME 底部边距时不启动。无效时设置页会显示最近的长按/补点状态。

### 实现与限制

- 无障碍服务仅在此选项开启时设置 FLAG_INPUT_METHOD_EDITOR，使用 getInputMethod/getCurrentInputConnection/sendKeyEvent，发送 KEYCODE_DEL 的一对 DOWN/UP。没有查询或保存输入文字，没有请求窗口内容读取或触摸探索能力；没有网络权限。
- 原固定触发窗口持续持有物理触摸，按住系统设定的长按时间后开始删除，每 80 ms 最多发一次。每个删除键均立即配对抬起，不留一个虚拟指针或按键持续按下。
- 仅在标记位置附近、屏幕尺寸与标记一致、系统检测到键盘显示且高度匹配、输入连接有效时启动。每次删除前重新确认键盘和同一个 EditorInfo；输入框切换、键盘收起、移动超出抖动容限、多指、系统取消、锁屏、关闭选项、服务断开或销毁均停止后续发送。
- 所有延迟任务带交互代数，松手后旧任务无效，不补发积压的删除，不把已经执行删除的长按转成一次点击。快速上滑在达到原有阈值前已取消删除计时。
- 这是对当前输入框发送删除键的辅助。各输入法的拼音候选、组合输入、特殊输入框或自定义编辑器兼容性仍需实机验证；不保证复现输入法自己的加速删除或候选处理逻辑。目标应用已排队的输入事件仍由目标应用处理。
- 标记范围为中心横向 36 dp、纵向 24 dp；不会自行移动或放大原悬浮入口，避免改变现有手感。
- 设置页保留「最近补点」并新增「长按删除」状态，不把系统接受请求当作目标应用已执行的证明。

验证：生产 DeleteHold 的短按共存、重复删除、松手停止、滑动取消、焦点/键盘失效、多指等统一取消路径、旧任务与 UI 卡顿检查；生产编辑桥与点按服务的平台替身检查覆盖开启编辑接口时仍能点按、删除键 DOWN/UP 配对、编辑器切换、结束输入和关闭功能后点按仍可用。API 35 编译与签名等安装包检查完成；尚未进行 Android 真机/模拟器运行验证。沿用原签名，versionCode 11。

可运行：`BLOOM_ECJ_JAR=/path/to/ecj.jar python3 tests/tap_service_protocol.py`；纯 Java 的 `DeleteHoldTest` 使用 ECJ/JDK 编译 DeleteHold、TapClassifier 和测试类后运行。

## 0.1.9 恢复版：撤回长按试验，恢复轻点与上滑

- 移除长按试验入口和触摸控制器接管代码；移除请求触摸探索的静态能力，升级时清除旧的长按选项，保留轻点开关、应用、位置、动画、最近任务隐藏与自启动设置。
- 入口窗口恢复普通点击/滑动接收；短按松手后仍按原流程让入口窗口透明且不可触摸，等待 32 ms，再在同一坐标补一次 24 ms 点击。上滑阈值、选应用与收起路径不变。
- 无障碍连接时始终清除本服务的触摸探索标记与触摸事件订阅；即使当前进程从未创建长按控制器，也会执行清理。防止只关闭开关却保留旧动态配置的情况。
- 仅在系统普通触摸模式就绪后报告点击服务可用。若系统仍在触摸探索模式，显示实际状态并保持键盘优先，不把未就绪状态当成成功。
- 设置页新增最近一次补点请求结果：尚未触发、系统完成手势、被系统取消或系统未接受请求。手势完成只代表系统回调，不保证目标应用一定执行了点击。
- 主机端回归覆盖：无长按对象的旧动态配置恢复、异步就绪、连续五次原坐标 24 ms 点击、系统取消/拒绝、解绑重连与其他触摸探索仍开启。该平台替身检查不能替代安卓真机验证。
- 原签名覆盖安装，versionCode 10。长按穿透尚未完成，暂不提供此开关。

安装 0.1.9 后，在系统无障碍设置中将「角落绽放 · 点击穿透」关闭再开启，返回应用开启轻点和角落手势。无需卸载。若仍失效，请查看设置页的服务状态与最近补点结果，以区分触摸没有进入入口、服务未就绪、请求被系统拒绝与目标应用未响应。

## 0.1.8 更新：修复原生长按模式无法上滑

- 修复原生模式遗漏事件订阅：AOSP 的 canReceiveEventsLocked 要求事件类型不为零，启用触摸探索还会检查该条件。0.1.7 只设置了手势能力与请求标记，可能导致系统没有启用触摸控制，而入口已被设成不可触摸，上滑失效。
- 仅在原生模式工作时动态订阅 TYPE_TOUCH_INTERACTION_START/END；不订阅窗口、文本或控件事件，不读取输入内容。关闭或失败时恢复原始事件类型。
- 调整初始化顺序：先配置能力与事件，再注册控制器。只有配置存在且系统确认触摸探索开启后，才把入口切换为不可触摸，并显示已就绪。1.2 秒内未确认则恢复原补点模式，避免假就绪。
- 新增主机端协议回归检查：用 AOSP 的启用前提模拟平台，运行生产 NativeTouchRelay 代码，重现旧配置的零事件掩码问题，并验证新配置的异步启动、上滑 DOWN/MOVE/UP、长按真实松手交接、关闭后恢复、初始化失败保护。该检查不是 Android/键盘设备测试。
- 保留 160 ms 长按判断、上滑阈值、位置、动画、实心图标及雾效。沿用原签名，可覆盖安装，版本号 9。

使用：覆盖安装 0.1.8 后，在系统无障碍设置中关闭再开启「角落绽放 · 点击穿透」一次，返回应用确认角落手势和原生长按选项开启，重新测试快速上滑和按住删除。尚需一加 Ace 5 实机验证。

运行本次协议检查：`BLOOM_ECJ_JAR=/path/to/ecj.jar python3 tests/native_relay_protocol.py`。

## 0.1.7 更新：免 Root 原生长按穿透（试验）

- 新增独立开关「原生长按穿透（免 Root · 试验）」，默认关闭，需 Android 13/API 33 及以上、已有无障碍授权及「轻点穿透」开启。保留旧补点模式作为回退，无 Root、Shizuku 或网络依赖。
- 在入口内按下后，最多保留 160 ms 判断窗口：达到原有 20 dp 上滑门槛即启动应用选择，之后保持同一条触摸序列；若保持按住则调用 TouchInteractionController.requestDelegating，由 Android 接管后续真实移动/松手，键盘自己处理连续删除。原生模式不注入固定时长长按、不发送重复删除键，也不在松手后开始删除。
- 160 ms 是交给键盘前的额外判断时间，输入法仍有自己的长按延迟；不是保证在 160 ms 时就开始连续删字。停留后再上滑会作为下层的原始手势处理；快速上滑不等这段计时。
- 入口的视觉窗口保持原来的位置/尺寸，原生模式下不可触摸且窗口 alpha 不超过系统允许的遮挡上限；动画画布与图标保持不透明，雾效不变。只让亮条窗口略降透明度以满足原生触摸通过规则。
- 实现需要动态启用无障碍的触摸探索能力。把整个屏幕减去入口区域设为触摸探索直通区；其他位置的原始触摸直接通过，初始化窗口期的回调也立即转交下层。仅入口内判断手势，不请求窗口内容或屏幕文字，不收集输入文本。
- 触摸探索的系统状态仍会开启，部分应用/输入法可能因此改变行为。其他服务已请求触摸探索时不启用试验模式，运行期间检测到冲突则退回补点模式；这不能替代一加/输入法兼容性测试。
- 关闭开关、停止入口、锁屏或无障碍断开时释放控制器、取消判断计时、清除直通区域并关闭本服务的触摸探索请求。若系统接口报错则回退补点。没有循环注入和迟到长按重放。
- 短于判断窗口的轻点仍沿用已有 24 ms 补点。多指在上滑展开前交给下层，展开后多指只取消选择，不生成下层点击。
- 版本号升至 8，沿用原签名，可覆盖安装。真机兼容性尚未验证。

### 使用新选项

1. 覆盖安装 `corner-bloom-0.1.7.apk`，原来的设置保留。
2. 在「轻点与上滑分开处理」打开「原生长按穿透（免 Root · 试验）」；保持「轻点穿透」和系统里的「角落绽放 · 点击穿透」无障碍服务开启。
3. 如升级后状态未就绪，到系统无障碍设置把该服务关闭再开启，使系统重新加载新增能力；回应用开启角落手势。状态应显示「原生穿透已启用」。
4. 在有一段可删文字的输入框中测试：触发区覆盖删除键时按住，确认连续删除，抬起确认立即停止；再测试轻点、快速上滑展开、取消和重复操作。
5. 如输入法/系统手势发生异常，关闭「原生长按穿透」恢复原补点方式，或从常驻通知停止入口。

## 0.1.6 更新

- 新增「后台与启动」设置：可隐藏最近任务卡片，可在开机并解锁后自动恢复入口。两个开关默认关闭，需用户自行开启。
- 隐藏任务使用 AppTask.setExcludeFromRecents；在开关变化及 Activity 恢复/离开前应用，不关闭界面或悬浮服务。仍可从桌面图标、常驻通知打开设置。
- 自启动接收 BOOT_COMPLETED，只有开关开启且已有悬浮窗权限才启动原 specialUse 前台服务；不启动 Activity、不提前读取锁屏前的数据。没有使用循环保活。
- 新增「轻点穿透（需无障碍）」开关，默认关闭。授权后入口固定显示在键盘上方：短按时暂时让触发窗口完全透明且不可触摸，在同一屏幕位置补一次 24 ms 轻点；上滑仍展开应用。
- 补点依赖用户手动启用的「角落绽放 · 点击穿透」无障碍服务，仅声明手势执行能力，明确不请求窗口内容读取能力，不处理屏幕文字或窗口事件。
- 无障碍未连接或功能关闭时，恢复原来的键盘优先层级。不会将长按、滑动、多指、系统取消或已激活的应用选择手势转成补点。
- 触发窗口在补点前等待 32 ms 让触摸布局生效，完成/取消后恢复；800 ms 超时兜底避免入口一直不可触摸。屏幕关闭、旋转、权限断开和服务销毁会清理待处理状态。
- 保持图标不透明、原来的雾效和固定窗口结构。版本号升至 7，沿用原签名，可覆盖安装。

## 安装与使用

1. 在手机上下载并安装 `corner-bloom-0.2.0.apk`。如果安装器询问，允许本次下载来源安装应用。
2. 打开「角落绽放」，先在「你的常用应用」里选择并排列应用，建议 9–15 个。
3. 在应用内练习区，从右下角亮条上划，保持按住并滑向图标，松手确认。练习区只提示结果，不会实际启动应用。
4. 点击「悬浮窗权限」，在系统设置里允许此应用显示在其他应用上层，返回后点击「开启角落手势」。通知权限用于显示常驻状态与停止按钮。
5. 切换到桌面或其他应用，从右下角亮条上划，不松手滑向图标，选中后松手打开。
6. 往角落滑回，或在没有高亮图标的地方松手，即可取消。也可以在应用内或常驻通知中停止入口。

触发区默认宽 16 dp、高 88 dp，距离屏幕底部 36 dp。可以调整距右侧/底部的位置、宽度、高度，以及展开范围、旋转回弹、入口亮条、触觉反馈、雾效强度和边缘柔和度。图标顺序按内圈到外圈排列。

一加 Ace 5：先保留入口亮条测试。如果与原有角落手势冲突，可以把触发区往上/左挪；若系统设置提供关闭原有手势的开关，也可以关闭后再试。程序不会自行修改系统手势设置。系统底部保留区域不保证可被第三方入口接管。

如离开应用后入口被系统回收，再检查系统对本应用的后台运行/电池限制设置，然后手动重新开启。如需重启后恢复，在「后台与启动」开启「开机自动启动」，并在系统应用设置中允许自启动和后台运行。

## 新功能设置

- 最近任务隐藏和开机自启动：在首页「后台与启动」分别开启。隐藏卡片后，通过桌面图标或常驻通知回到设置。重启恢复依赖系统广播、悬浮窗权限和厂商后台策略；被系统强行停止后，需要手动打开应用恢复广播资格。一加如未自动启动，请进入本应用的系统设置检查自启动、后台运行和耗电限制。
- 点击穿透：在「轻点与上滑分开处理」开启开关，再到系统无障碍设置开启「角落绽放 · 点击穿透」。授权完成回到应用后状态应显示「已就绪」。开启悬浮入口后，轻点仍在同一坐标点击下层按钮，上滑展开。入口保持原位置，不随键盘上移。
- 这是「松手后补一次短按」，不是原始触摸流穿透：有少量延迟，不转发长按、多指、横向手势或滑动输入；连续快速操作和不同输入法需要实机验证。Android 的手势注入可能中断当时进行中的其他手势，因此只在识别到单指短按松手后请求一次，不自动重试。
- 无障碍权限完全由用户在系统中手动控制。若系统限制侧载应用启用无障碍，需要在系统应用设置中允许相应的受限设置后再授权；不开此权限仍可使用原启动器。

## 第一版范围

- 原生 Android Java + Canvas；最低 Android 8.0（API 26），编译/目标 API 35。
- 最多 15 个本机可启动应用，搜索选择、手动排序，固定布局。
- 同一份手势与绘制代码用于应用内练习区和真实悬浮入口。
- 固定小触发窗口持续接收同一触摸序列，并按原始屏幕坐标交给独立的全屏动画画布；展开和取消不改变两个窗口的位置或尺寸。
- 应用内可见操作启动前台服务，常驻通知有停止按钮；锁屏时隐藏入口。
- 基本启动器不需要 root、API Key 或网络。仅可选的点击穿透需要手动授权无障碍；未声明网络权限。
- 按多个手指、收到系统取消或旋转屏幕时，取消当前选择。

## 构建

用 Android Studio 打开项目，安装 Android SDK 35，使用 JDK 17 和 Gradle 8.9 或兼容版本，运行 app 模块。项目未包含 Gradle wrapper；也可以通过本机 Gradle 执行 `gradle :app:assembleDebug`。

也提供不需要 Gradle 的构建脚本：安装 SDK platform 35、build-tools 35.0.0，设置 `ANDROID_SDK_ROOT` 后运行：

```bash
bash tools/build.sh
```

脚本需要 JDK 的 javac；只有 JRE 时，可通过 `BLOOM_ECJ_JAR` 指向 Eclipse ECJ 编译器。生成位置：`app/build/manual/corner-bloom-0.2.0.apk`。

签名密钥未纳入 Git 仓库。早期私下交付的备份压缩包可能包含本地测试签名，不应上传或分享该压缩包。

运行布局检查：

```bash
mkdir -p app/build/geometry-test
javac -d app/build/geometry-test app/src/main/java/dev/corner/bloom/FanGeometry.java tests/GeometryTest.java
java -cp app/build/geometry-test GeometryTest
```
